# P10-10 账户级组合风险验证

联合集成基线为 origin/main 的 5a1be4d34f6222c186937bea3ac7c90b9d675a14，包含 P10-07 动态资本管理。
工作分支为 feat/p10-10-portfolio-risk。场景使用离线 HTTP 回放、合成券商事实和本地 SQLite。

## 准入和风险度量

Binance Demo 与 Alpaca Paper 的共享账户执行都通过 PortfolioExecutor。策略原始订单、所有权和
资金预留先进入现有 outbox，由同一账户 SQLite 写事务串行化。CapitalPolicy.validate_orders
保留现有实例、标的及账户预算，组合规则在同一函数内追加约束。两家生产适配器在原有 POST
前账户读取完成后，将该轮事实交回同一函数。行情有效性、报价时限、市场规则、所有权、券商
权限和下层执行预算继续由原有组件检查。

账户报告通过 PortfolioExecutor.portfolio_risk_snapshot(account_id) 获取。报告同时提供按账户、
逻辑策略和执行实例划分的风险贡献、标的集中度、订单风险及现有 CapitalPolicy 的公开资金报告。
风险快照使用官方账户观察时间，标明缺失项和对账状态。

| 度量 | 计算口径 |
|---|---|
| 官方权益和现金 | Alpaca 使用 equity 和 cash，现金可用额以 cash 与 buying power 的较小值为上限。Binance 使用同一观察批次的保证金权益、钱包与可用保证金，或通过同批钱包和未实现损益计算权益。 |
| 已确认库存 | 按券商原始仓位身份汇总。合计持仓市值以绝对数量乘官方标记价格计算。策略仓位归属须与账户仓位数量及方向一致。缺失归属的策略持仓贡献为未知。 |
| Gross / Net Exposure | 经济敞口基于持仓名义价值和标的乘数。Gross 对各仓位取绝对值再相加，Net 按方向加总。 |
| 潜在风险 | 对开仓及加仓订单按原 client order ID 合并交易所和本地记录，按剩余数量乘原预留价和经济乘数。Binance 已接受但尚未生成组合订单的冻结意图直接参与同一投影，正式子订单提交后不再重复计算。部分成交转入已确认库存，退出预留保留既有所有权规则。尚不能定价的已接受决定或未准备买入标的使投影保持 UNKNOWN，阻止新增风险而不阻止合法减仓。 |
| 撤单中风险 | 未取得原订单终态前，开仓剩余数量继续占用额度，并同时计入撤单中的风险分项。 |
| 集中度 | 单标的假设该标的在途开仓全部成交，以该标的总经济敞口除以假设成交后的标的敞口与其他已确认标的敞口之和。其他标的的未成交订单不稀释集中度。 |
| 现金及保证金 | 使用券商已反映的现金和初始保证金。尚未反映的本地开仓按名义价值及配置费用增加现金预留。未反映的初始保证金按全额名义价值保守预留，缺失保证金保持未知。 |
| 收益及净值 | 账户净值为官方权益。已实现损益、归属的资金费及策略净值消费现有 CapitalPolicy 资金报告。Binance 官方权益已经反映结算后的资金费。 |
| 回撤与亏损 | 以持久化高水位、UTC 日内首次健康观察和滚动窗口基线计算。日内及滚动亏损以结算币金额表示。滚动基线取窗口起点前一小时内最近的保留样本，每小时保留首个健康观察。基线缺失时，已启用的对应亏损限制阻止新增风险。 |

TQQQ 的乘数影响经济敞口和集中度。100 USD 的 TQQQ 名义仓位按三倍乘数产生 300 USD
经济敞口，已投入现金仍为 100 USD。分红和拆股消费现有公司行为确认，拆股更新实际份额和
标记价格，分红反映已经入账的现金。

账户配置可使用 PortfolioExecutor.configure_portfolio_risk(account_id, limits,
economic_multipliers=...) 写入本账户的共享数据库。PortfolioRiskLimits 的阈值默认为未设置。
配置存在时，可单独启用总敞口、单标的总敞口、逻辑策略敞口、集中度、初始保证金、最低
可用现金、回撤、日内及滚动亏损、新增订单名义规模或账户事实年龄。金额采用本账户的结算币，
回撤及集中度采用 0 到 1 的比率。配置和净值历史随共享账户数据库恢复。仅开启组合规则
不会扩大任何现有执行预算。

## 风险响应

| 情形 | 执行动作 |
|---|---|
| 事实健康且投影符合限额 | 正常提交。 |
| 新增风险超过当前账户、策略、标的或订单约束 | 拒绝新增风险，保留原始身份与拒绝原因。 |
| 显式暂停策略或标的，或停止全账户新增风险 | 按配置作用范围拦截开仓和加仓。账户级停止在该配置被显式修改前持续有效。 |
| 显式启用超限撤单 | 在原账户轮次内，按可见的真实订单和未解决的提交重新计算风险，并通过原订单交易所撤单路径处理已确认归属的开仓。 |
| 所有权和市场事实支持合法减仓 | 新增风险阈值不参与减仓判断。Alpaca 继续检查自有库存、已预留数量和券商可卖数量。Binance 走现有 reduce-only、实例归属和执行能力检查。 |
| 显式武装紧急减仓 | 操作方可以预注册 emergency_only 退出计划，指定可触发的组合限额，并通过 run_emergency_reduction 执行。该计划在 POST 前使用当轮事实再次判断触发条件。 |

数据恢复后普通新增风险逐次重新计算。现有实例硬暂停、账户硬停止、Demo 交易授权及原有
累计亏损、次数和名义额预算由原控制机制管理。

## 数据边界

Binance 账户独立使用 USDT，Alpaca 账户独立使用 USD。风控公式在各自结算币上运行。
生产接线沿用原来账户轮次和认证读取，外部现金流补读同一账户的官方历史。跨券商显示如需汇总，
应由管理或研究端提供单独的汇率来源及时间。实时准入不消费跨券商总数或研究相关性、协方差和
压力模型，避免研究参数过期影响基础执行风险控制。

公开账户观察支持 cumulative_external_cash_flow。首次健康的已知流量保存为 initial_flow，
调整权益等于官方权益减去累计外部净现金流相对该基准的变化。首次观察若已含 1,000 USD
入金，且权益为 1,000 USD，调整权益仍为 1,000 USD。以后纯入金和出金不改变该口径下的
权益，交易盈亏则会改变权益。日内及滚动亏损和高水位回撤使用这个金额序列。正式 TWR 按
外部现金流划分子期间并将期间收益率连乘，和这里的加减金额口径有区别。同账户策略之间
的分配与转移只影响策略资金报告，不进入账户的外部资金流字段。

Binance 从官方 `/fapi/v1/income` 的 USDT `TRANSFER` 读取带符号的外部现金流，复用协议库
`futures_income_coverage` 保存累计值和一小时重叠窗口；超过现有 90 天历史保留边界的断档保持
UNKNOWN。Alpaca 从 `/v2/account/activities` 的 `CSD`、`CSW`、`ACATC` 读取 `net_amount`，
复用协议元数据保存累计值和七天结算日期重叠窗口。日记账及证券转入转出无法仅凭类型确认外部
现金价值时保持 UNKNOWN。两家均按官方身份替换重读窗口，不生成经济过账或新增账本。

资金流未知时不使用原始权益估计亏损。从未知变为已知时采用首个健康观察重建基准，并清除旧口径
的滚动样本。旧数据库中已使用调整口径但缺少原始流量基准的记录也按同样方式重建。建立基准后
流量暂缺时，保存现有高水位和基准，当前亏损、回撤标记为未知。P10-07 的资本事件是同账户策略
与公共池之间的内部划拨，不进入 cumulative_external_cash_flow；策略绩效按事件保存的流前权益
与追加、撤回金额连接收益，组合亏损继续只消费账户外部流量口径。

官方字段参考：[Binance connector income 合同](https://github.com/binance/binance-futures-connector-python/blob/main/binance/um_futures/account.py)、
[Alpaca account activities](https://docs.alpaca.markets/docs/account-activities)。

## 复现

在 worktree 根目录将 PYTHONPATH 指向当前 src，保证重启场景的 Python 子进程也导入本分支。

~~~powershell
$env:PYTHONPATH = (Resolve-Path src)
python -m pytest -q tests/trading tests/integrations/test_portfolio_account_risk_http.py tests/integrations/test_shared_portfolio_execution.py tests/integrations/test_demo_portfolio_adapter.py tests/integrations/test_binance_demo_execution.py tests/integrations/test_alpaca_portfolio.py tests/integrations/test_alpaca_instance_runtime.py tests/integrations/test_alpaca_http_recovery.py
~~~

HTTP 场景验证两个策略同时提交订单、合计敞口和共享标的约束、未成交订单不能稀释集中度、
分范围暂停、部分成交、未确认撤单、账户事实及报价过期、撤单与停止状态重启恢复。Alpaca
场景验证 TQQQ、分红、拆股、资本快照更新及同一策略紧急减仓。Binance 场景验证已知及未知
官方保证金、资金费导致净值下降、日内及滚动亏损、累计外部现金流调整和原始 reduce-only
退出。相邻回归覆盖历史策略的现金、所有权、对账和账户预算路径。

风险历史以账户为键持久化一个高水位和日基线，再保存最多约 31 天的小时基线。活动订单通过
SQLite 部分索引读取，风险计算不引入历史行情加载。日志 portfolio_risk_calculation 记录每次
计算的线程 CPU 时间、计算经过时间和进程高水位 RSS。显式请求财务报告时复用现有历史账本。


## PR #266 复审修订

Alpaca 的账户恢复先从官方 API 获取订单、活动和持仓事实。共享账户 tick 使用
PortfolioExecutor.reconcile 将同一批原订单和成交活动导入组合账本，再用该轮账户持仓
执行超限撤单。10 USD 部分成交计入实例库存，原 20 USD 开仓订单剩余 10 USD 继续占用
额度。HTTP 用例通过真实 Alpaca 适配器验证此时 100 USD 上限下不发送撤单，且正常 tick
仅读取一次持仓。标记价格变动后真实超限仍按原订单撤单，撤单回执未确认时保留预留，重启后
继续沿原身份恢复。未归属持仓保持未知，并触发现有的所有权风险响应。

补齐上一轮扩展 CI 发现的两个 Binance 调度场景的执行器夹具，验证调度器向组合风控传递
原账户身份。Alpaca tick 和 Binance 调度的定向回归共 12 项通过。另有 3 项 SQLite 净值
用例验证已入金初值、存取款、交易盈亏、日内与滚动亏损、重启和旧状态迁移。Binance HTTP
场景从已经包含历史入金的账户启动，验证期初回撤为零，成交费用计入后续回撤，出金本身
不构成交易亏损。

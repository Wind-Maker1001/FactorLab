# P10-14 — Internal incremental recovery foundation

## Delivery boundary

This delivery covers original internal transaction admission and replay, not an executable cross-region disaster-recovery system. Azure fencing, automatic takeover/publication, production replication wiring and new coordination services are deferred. Replicated execution stays quarantined and activation stays disabled. Existing non-replicated Binance and Alpaca execution has no offsite-confirmation dependency or additional resident process.

New portfolio creation prepares the complete outbox in a rolled-back SQLite write transaction, reusing projected capital/risk checks against all tentative reservations. One original event then applies policy claims/ceilings, inventory attribution, multipliers/history, plan and orders in the portfolio reducer transaction. Network confirmation occurs after rollback. Atomic creation, original order observations, legacy execution and risk admission regression passed 62 tests in 56.23 seconds.

Original POST markers can include prepared adapter dispatch consumption in the same account event. The Binance runtime preparation preserves cumulative dispatch and affected exit-budget reservations; Alpaca preparation preserves original adapter intent, price reservation and submission-rate window. Cross-database application is resumable, not distributed atomic commit: the account remains isolated until every domain reaches the same cut. Adapter-specific fault and legacy execution regression passed 81 tests in 20.93 seconds. Fault cases cover lost ACK, interrupted domain application, original-window replay and source database removal; no broker POST is issued by preparation or replay.

Targeted independent review identified two defects, both fixed and independently rechecked: an original Alpaca identity discovered during GET recovery must be rejected before proposing a new admission; original recorded-risk rejection confirmations must be included in the atomic plan event. The final affected capital/NAV/dispatch run passed 38 tests with one new fixture failure (missing the required multiplier argument); after correcting that fixture, both accepted/rejected atomic-plan tests passed in 3.00 seconds. An earlier invocation named a nonexistent risk test file and collected no tests; the corrected run used the NAV test file. The original capability audit below records uncovered interfaces as well as implemented primitives; it does not authorize execution.

File sizes describe database files at observation, not WAL size, replication traffic, memory use or recoverable data loss. Schema inspection is not a cross-database data snapshot.

The observed Binance controller has `events`, `snapshot` and `demo_order_owners`, but no `demo_instance_outbox`. The observed Binance root has no account portfolio database. Recovery coverage must nevertheless include these stores when the multi-instance execution path creates them. An inventory of the deployed legacy path is not sufficient qualification of the multi-instance path.

The observed Alpaca market-stream database is 843,018,240 bytes and contains market events and gap observations. It is not a financial recovery prerequisite. Observed Alpaca account, portfolio and deployment files are respectively 77,824, 294,912 and 196,608 bytes. The Binance controller file is 29,614,080 bytes. Copying a complete controller snapshot for every small state change would require measurement before it could be considered lightweight.

### Recovery classification

`OFFICIAL` means original exchange/broker evidence can be fetched, subject to API history coverage and complete pagination. It does not recover internal ownership. `INTERNAL` means original internal state or a complete authoritative internal event is required. `DERIVED` requires all listed original inputs and the compatible calculation implementation. `CACHE` is regenerable and does not establish ledger completeness.

### Cross-database causal boundaries

1. `OrderStrategyRuntime.decide` commits a decision and checkpoint in the deployment database before invoking execution, then acknowledges dispatch separately. A valid cut may include an outstanding decision; replay must preserve its original receipt and execute/reconcile it idempotently, not discard it or rerun strategy inference.
2. `DemoInstanceExecutionAdapter.execute` serializes against the portfolio transaction and commits controller ownership and acceptance outbox state. Plan materialization, venue dispatch and outbox completion follow in separate transactions. Restore must retain the accepted outbox before interpreting a plan or POST reservation as unowned.
3. `DemoRuntime.reserve_instance` persists dispatch/budget authority before HTTP. Venue GET cannot determine whether every failed or uncertain attempt consumed internal cumulative budget.
4. TaskMailbox producer and execution consumer commit separately. Restoring only a receipt or only the portfolio can respectively skip an unexecuted task or recreate an already accepted task. Match original task/decision/plan IDs before advancing consumption.
5. Alpaca raw account state, portfolio postings, deployment decisions and runtime cash anchors live in separate databases. Raw fill completeness is not portfolio ownership or checkpoint completeness.
6. C07 currently obtains the market ownership lock and SQLite write reservations across the inventory before copying databases. This is a coherent stopped-writer snapshot mechanism, not an online transaction-change feed. Periodically opening each database independently would not preserve its causal guarantee.

### Existing journal sufficiency

The current `events` table is not a complete reconstruction source. Strategy desired state is updated in place in `strategy_control`; deployment checkpoints and switch state, Alpaca metadata/order uncertainty, capital configuration and risk high-water state are persisted outside that journal. Original capital events are useful and must be reused, but they do not by themselves supply complete cross-store commit coverage.

A row count, matching official cash/inventory, or a contiguous received sequence proves neither complete internal coverage nor absence of an unreplicated tail.

There are two separate proof requirements:

- **Received-prefix integrity:** detect missing, partial, conflicting and out-of-order batches and replay the complete received prefix.
- **Source-tail completeness:** establish whether internal commits occurred beyond that prefix. A source that has permanently disappeared cannot report its final watermark. Asynchronous ACK age or heartbeat does not prove absence of a later capital/control event.

To publish a source-loss execution state without unexplained internal tail risk, either an authoritative final state must become available, or non-reconstructable internal changes must have an externally durable admission/decision before taking effect. An ACK barrier applied only after the local SQLite commit leaves a crash window and is insufficient. This requirement must not be hidden by labelling a stale prefix complete.

## Ownership conditions

The selected route is infrastructure fencing through Azure. P10-09 validates an administrator-owned attestation; validating that file is not itself enforcement of VM isolation. Read-only Azure identity inspection found a managed-identity token on the current source VM, but the VM-scoped permissions enumeration returned an empty list with no pagination. The standby VM's default managed-identity token request returned HTTP 400. The administrative Cloud Shell identity was separately inspected at both VM scopes: both permission results included actions `["*"]`, empty `notActions`, and no next page. This establishes a management context for configuring isolation, not an automation identity or enforced fence. The intended runtime control-plane identity and restart restrictions still need to be established. The implementation must verify durable prevention of source restart and unique target publication, including simultaneous takeover and reverse handoff. A deallocated VM alone can subsequently be restarted; inability to reach SSH is not fencing.

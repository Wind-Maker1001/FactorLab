## 机器文件与状态合同

`data-admission-matrix.csv` 的156条 `record_scope=TABLE` 是唯一覆盖分母；少量 `USE_CASE` 行重用同一表的统计，不可再次汇总行数或分片。`actual_scanned_rows`、`inherited_evidence_rows`、`declared_rows`、`total_physical_rows`、`unscanned_rows`分列；空单元格表示未知/未单独建立，不是0。`asset_scope`绑定登记资产，精确成员身份沿证据引用回溯DQ-01原分布与各审计回执。

内容枚举：`FULL_CONTENT_SCANNED`为登记范围全部数据行/列被访问；`PARTIAL_CONTENT_SCANNED`仅部分范围访问；`METADATA_ONLY`仅目录/元数据；`NOT_VERIFIED`无可用验证。它们都不代表金融语义认证。

键枚举及解释在 `evidence-index.json`：只有已确认业务唯一键合同加完整精确检查才可 `KEY_EXACT_VERIFIED`，本轮没有此状态。候选精确、资源阻断、合同未知、观察冲突与未评估分别保留。

研究枚举：`READY_SCOPED`只限精确对象及已验证用途；`CONDITIONALLY_USABLE`为满足所列条件的有限探索，**不是可直接接入模型的数值准入**；`BLOCKED`为已知缺口直接阻断该用途；`NOT_ASSESSED`为证据不足。semantic状态只用 `NOT_ASSESSED` 或 `SCOPED_EVIDENCE_ONLY`，PIT/HFQ独立保持未认证。`confidence=HIGH`表示提交证据支持该计数或限制，不是金融正确性的概率。

`research-impact.csv`区分已观察输入/执行/账户问题、实际证据缺口、潜在风险和已有隔离保护；`remaining-work.csv`只列最小补证，不把全库重扫作为解决方案。

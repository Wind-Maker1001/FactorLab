## 定向剖析

在实现前，从认证快照按 F02 原生成器重建三个模型的 `seed=1729, path_id=0`，每条 168 步。以 F02 的 Anaconda CPython 3.12.7 和 SQLite 3.45.3 做一次无插桩回放，再做一次调用边界回放。无插桩合计 10.1629 秒墙钟、3.4219 秒 CPU。插桩合计 9.7600 秒墙钟、3.5156 秒 CPU，进程生命周期峰值 RSS 174,153,728 字节。三个账户共 2 笔成交，按原口径取全部账户残差。

计时按调用边界扣除被单独计量的子调用。SQLite BEGIN、COMMIT 在连接调用处计数，初始化 DDL、关闭及 WAL checkpoint 的外围成本没有单独量出。FIFO 核心只用了 0.0007 秒。CSV 读取使用 pandas 边界和 FIFO 准备边界计时，后者还包括遍历导出。账务时间包含各 bar 的 NAV 投影，拆分数值不含主进程的整组统计和模型生成。插桩比无插桩墙钟低 4.0%，CPU 高 2.7%。这是一次成对测量的运行差异，不能把差额解释为插桩开销。该机的短周期 CPU 读数以约 15.6 ms 为粒度，因此只对总 CPU 和墙钟归因作判断。成交密集账户在这个剖析样本内代表性有限。

单账户反复提交 WAL+FULL 写事务，墙钟等待大于 Python 处理时间。账户之间可重叠这部分等待。每次导出顺带执行 Git 与环境检查的代价居第二位，同一次运行可复用启动时采集的来源。文件解析占比较小，因此保持原先的 pandas 与 Decimal 处理路径。

## 实现和准入

`mc_grid_tail_convergence.py` 仍在主进程生成完整模型批次、隐状态及正式结果。每个任务接收已生成的价格序列，在独立临时目录中使用原有 Grid、PaperBroker、TradingController 和 PaperStore。每次回放将临时 SQLite、WAL 和完整账户导出清理后，才返回指标与隐状态诊断。默认串行。开启并行时使用 Windows 兼容的 `spawn`，设置 1–8 的整数上限，在途任务数不超过所选 worker 数。主进程沿定义中的模型、种子和自增路径号消费结果，保持同 NAV 的原有首次命中规则。这样也保留了分组输入顺序以及 VaR/CVaR、收敛计算的分母。

整组资源预测沿用原定义的成本和时间储备，并行配置没有把预测按 worker 数折减。定义提供单账户 scratch 规划时，并行回放会在组前检查相应并发空间。可捕获的空间不足、worker 报错和中断会留下 `failure.json` 并传播异常。中断时逐行 `paths.csv` 仍可包含诊断前缀，正式计数来自上一个完整组及其 `groups.json`，本次失败运行不会发布成功摘要。

`grid_paper.py` 和 `grid_monte_carlo.py` 允许 MC-05 为账户清单提供同一份来源凭证，各自独立调用仍可采集来源。账本、WAL+FULL、订单状态机、Decimal FIFO 和 NAV 投影继续走原实现。Demo 的交易、授权与恢复通过既有入口。CLI 增加 `--max-workers`，运行定义单独记录调度参数。

## 有界基准

用 Python 3.14.0、NumPy 2.3.4、pandas 2.3.3、SQLite 3.50.4 和 Windows 11（i7-14700KF、约 64 GiB RAM）。从 F02 定义派生独立的基准定义，将模型设为 `['jump_down']`、`sizes=[8]`。原始种子 1729、2718、31415，批大小 8、168 小时、模型参数、成交条件和 999 次重采样直接沿用。正式冻结运行仍使用原定义。下表来自同一台机器按 1、4、8 各运行一次的顺序，24 个账户与三次输出目录各自隔离。

| 账户数 | 24 | 24 | 24 |
| 研究入口墙钟（秒） | 61.3557 | 36.6600 | 25.5093 |
| CLI 冷启动到退出墙钟（秒） | 67.3535 | 38.8701 | 27.6790 |
| 账户/秒（研究入口） | 0.3912 | 0.6547 | 0.9408 |
| 加速比（研究入口） | 1.00× | 1.67× | 2.41× |

研究入口墙钟含整组生成、统计、证据写出、worker 启动及销毁。另从 CLI 启进程到退出计时以显示导入和初始快照装载成本。CPU 来自 Windows Job 的用户态加内核态记账，包含 Python 子进程和 Git 进程。RSS 和临时文件长度按约 100 ms 采样，RSS 会重复计入共享页，二者可能遗漏采样间峰值。临时盘包括活跃 SQLite、WAL、SHM 和账户导出，正式输出另存。前缀的总账户执行墙钟之和为 60.45、133.93、171.35 秒，随并发增加，相当于单账户平均从 2.52 秒增至 5.58、7.14 秒。这与多个 WAL+FULL 提交争用同一存储路径相符。该基准没有进一步拆分存储争用与有序等待。8 workers 相对 4 workers 再缩短 30.4% 的研究入口时间，同时多用 10.13 秒总 CPU。三档均未超预算，验证范围到 8 workers。

三档各有 18 个账户成交，共 26 笔，最差路径均为种子 2718 的路径 2，期末 NAV 984.467386885566。三个配置的账户 CSV（排除临时文件字节数）、分组统计、VaR/CVaR、隐状态、模型批次元数据（排除耗时）及最差路径价格逐项相同，数值比较零容差。与历史前缀对比，除两列自相关外其余共同账户字段精确相同。收益与平方收益一阶自相关的最大绝对差分别是 1e-16 和 8e-17，分别涉及 18 行和 21 行。该对比跨解释器和数值库版本，差异局限于价格诊断。三档间这两列也精确相同。

两项实际 `spawn` 回归覆盖种子与路径身份、Regime 隐状态、拟合批次回执、NAV 并列和整组失败。另对成交、部分风险退出及提交拒绝分别做短账户对照。拒绝样本通过测试夹具把 Paper 控制器的下单频率阈值设为每分钟 1 笔。三条路径逐条比较 SQLite 终值快照、按序 journal、完整 Decimal FIFO（含匹配与未平仓批次）、`daily.csv`、`trades.csv`、`result.json`、`evaluation.json` 和账户清单，串行与 `spawn` 精确相同。退出样本有 3 次取消回报、3 次部分成交回报和一次风险触发。120 项定向测试在 Python 3.14 通过，范围包含已冻结证据引用与 Paper 控制器。

重放基准时，使用 F02 报告引用的认证快照，复制 `configs/mc05_f02_grid_tail.json` 到新目录，将 `models` 和 `experiment.sizes` 改为上述子集，使用三个独立输出目录依次各运行一次。将 `--max-workers` 分别设为 1、4、8。正式定义和输出目录无需编辑。

```text
python tools/research/run_mc_grid_tail_convergence.py --snapshot <F02-snapshot> --definition <prefix-definition.json> --output <new-output-dir> --max-workers 1
```

# P7-M19-F08 Grid 轮换验收

## C04/F08 离线集成

集成基线为已合并 C04（#222）的 `05df99fb77ccdf751df45977edec15d97411085e`。C04 的 systemd Execute 仍通过同一个 `GridSupervisorRuntime` 获取账户执行锁、延迟打开会话并执行 GET 恢复。恢复后，同一个 Consumer 检查策略突破和账户事实，提升替换部署，并在原行情游标上等待下一根符合条件的实时 Bar。预检、会话恢复及订单准入共用部署身份校验，核对持续授权、Campaign 和持久部署继承记录。

Windows Python 3.14.10 回归使用临时 SQLite 状态、确定性时钟和离线 HTTP 模拟器，覆盖挂单阻止轮换、原游标连续、首根新鲜 Bar 使用新命名空间、重启恢复挂单及历史手续费、Campaign 续期后预算连续、预算耗尽时健康检查拒绝交易、STOP/HALT 并发和用户 PAUSED。真实 systemd 的 SIGTERM、SIGKILL、互斥启动和轮换后的独立进程恢复由现有 Ubuntu CI 的离线回环场景验证。

本次集成未启动官方 Binance Demo Execute，未调用真实 POST/DELETE，未读取台式机的私有账本。下方记录的是集成前的官方历史证据。本次没有新增官方成交或手续费证据。

本轮沿用 [F05 报告](../p7-m19-f05/REPORT.md)、[F05 验收数据](../p7-m19-f05/acceptance.json)和同一个 Windows Demo 状态根。执行前用现有 `demo_fill_acceptance` 独立捕获账户快照。官方 GET 确认账户平仓、无挂单、`UNKNOWN=0`，钱包为 `4999.97114760 USDT`，历史手续费为 `0.00325240 USDT`。

原部署 `fl-d7345f8795464a65-g` 保留区间 `[159.47, 162.71]`。从原命名空间重放 9,193 条已保存的 Grid 命令，状态仍为 `PAUSED / BREAKOUT`。新部署的不可变记录指向原部署，各自的 Grid 命令独立写入，同一账户的订单、成交和手续费仍由原账本记录。行情源沿用原执行游标。

03:00:27，新部署 `fl-d7345f8795464a65-g-00001` 以官方 Demo 卖一价 `130.90 USDT` 生成 `[129.59, 132.21]`。策略为一层算术 Grid，单次使用 `0.04 NVDA`，突破暂停，订单 TTL 为 100 根 Bar。交易所下单步长和最小数量均为 `0.01 NVDA`，价格刻度为 `0.01 USDT`，最小名义额为 `5 USDT`。

### 订单与独立进程恢复

03:01:00 的新鲜闭合 Bar 走原 Grid 信号路径。原执行网关提交 `BUY LIMIT GTC 0.04 NVDA @ 129.59 USDT`，名义额为 `5.1836000 USDT`。订单 ID 后缀为 `-00001-00000001`。Binance POST 返回 HTTP 200、`NEW` 和交易所订单 ID，随后官方订单 GET 返回相同的两个订单标识与订单参数。账户事实的观测时刻距 ACK 约 3.10 秒，执行网关在发送前应用五秒账户读集门槛。

首个 Execute 窗口结束后，现有导出器以两个独立进程获取签名 GET 证据，得出 `UNCHANGED`。进程重启前后的订单事实、持仓、账本经济事件、钱包和手续费一致，且 dispatch 计数未增加。首轮快照显示挂单数 1、成交量 0、`UNKNOWN=0`，历史账户 FIFO 与权益对账残差为 `0E-8 USDT`，NAV 为 `0.99999422952`。

第二个 Execute 进程恢复了同一部署，从原水位继续运行至 03:20:00 的闭合 Bar，发出 0 POST、0 DELETE。之后的独立 GET 导出再次得出 `UNCHANGED`。最后一次官方订单 GET 仍为 `NEW`，`userTrades` 对该单返回空记录。账户保持平仓，挂单数为 1，`UNKNOWN=0`。钱包、权益、FIFO、NAV 和累计预算保持首轮末值。两次有界 Execute 窗口均已结束，该 GTC 限价单留在 Demo 交易所，连续授权仍为 RUNNING。

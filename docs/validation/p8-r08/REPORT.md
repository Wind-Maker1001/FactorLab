## 8. 下一轮策略与工程改进建议（按证据优先级排序）

1. **【P0 / 最高优先级】引入资金费率感知风控（Funding-Aware Holding / Weekend Guard）**：本次实证最核心的经济发现是，仅 8 小时高资金费（`-0.0976 USDT`，均率 `22.97 bps/h`）就吞噬了 Gen 1 `73.96%` 的交易毛利。建议下一轮研究在**不改当前在线参数的前提下**先做离线对照：监控交易所实时/预测资金费率（`/fapi/v1/premiumIndex`），当正资金费率超过阈值（如 `> 5 bps/h` 或美股休市周末溢价期）时禁止新开多头网格或缩短持仓最大账龄上限（`max_inventory_age_hours`）。
2. **【P0】核查并消除 F11 在低流动性/下行突破时的退出延迟与成交风险**：本次 F11 实证为**上行突破**（买在 `129.59`、退出在 `132.89` 盈利平仓），尚未观测到**下行突破**（亏损方向）时的减仓限价单成交率与滑点；同时应确保云端 systemd 持续在线，避免再次出现 Windows 时代的 7.7 小时离线滞留。
3. **【P1】评估单层 `±1%` 网格的盈亏比与 `max_cash_committed = 7.00 USDT` 价格上限脆弱性**：历史回放显示，当 `NVDAUSDT > 175 USDT` 时，最小交易量 `0.04` 的名义额即突破 `7.00 USDT` 硬上限导致无法下单；且单层 `±1%` 网格在 7 天内高频触发 `BREAKOUT` 暂停。下一轮离线研究应评估：① 按价格自适应 `quantity_unit` 或明确定义预算与最小名义额的耦合告警；② 对比 `±1%` vs `±1.5%~2.0%` 与多档位（2–3 levels）在相同 7–10 USDT 风险预算下的循环完成率与尾部 CVaR。
4. **【P1】建立按日/按周增量自动更新流水线**：复用本次交付的只读快照抓取脚本 `tools/research/capture_demo_ro_snapshot.py` 与绩效报告脚本 `tools/research/run_demo_grid_r08.py`，待 Azure 跑满 24h / 72h / 7d 观察窗并积累多轮常规网格循环（含下行突破样本）后，一键重跑更新本报告，不手工重新核算。

# 发行人支付安排与模拟结算资格

九事件均有正式实施公告。沪市公告“相关日期”列明现金红利发放日；深市公告“权益分派方法／办法”列明中国结算深圳分公司经托管证券公司划入账户的日期。各事件对应原件及章节见 event-evidence.json。

|资格|本轮解释|九事件结果|
|---|---|---|
|ISSUER_IMPLEMENTATION_VERIFIED|取得实施而非预案原件，核对发行人代码、法定名称、日期与现金条款|true|
|ENTITLEMENT_VERIFIED|限定冻结研究账户、登记日收盘股数与原成交重建一致|14个交集true|
|PAYMENT_DATE_VERIFIED|正式披露的支付安排日期，不是实际执行结果|true|
|SIMULATED_SETTLEMENT_BY_RULE|显式选择条件模拟政策，公告支付安排及分配办法均绑定原件|条件情景true|
|ACTUAL_ACCOUNT_PAYMENT_VERIFIED|需要真实券商／结算到账凭据|false|
|TAX_UNVERIFIED|没有投资者税务资格与实际扣缴合同|全部保留|

模拟政策假设研究账户持有普通无限售A股，不属于发行人自派对象，指定交易与托管有效，发行人及中国结算按公告执行。沪市未办理指定交易的红利由中国结算保管，深市及沪市各公告还列明自派对象；不能把这些例外悄然认定为已满足。本轮明示采用普通交易持仓情景，不声称存在这些模拟账户的真实证券登记或券商流水。每份公告的分配实施办法本身是限定适用规则证据，没有把未取得的中国结算内部确认文件列为已读取。

默认 `ACTUAL_ACCOUNT` 模式下，九事件在除息日确认应收，缺实际到账凭据时不支付。选择 `SIMULATED_BY_RULE` 才生成 `SIMULATED_SETTLEMENT_BY_RULE` 日记账。它要求独立的发行人支付安排ID和结算规则ID，不接受仅一个候选支付日期；实际账户支付字段仍为false。二者复用同一适配层，不建立第二个执行器或NAV系统。

模拟账的 `paid_cash_gross` 表示所选结算basis内的累计转账，同时显式提供 `simulated_cash_gross`；它不是实际到账金额。税前累计收入只在除息日确认一次。支付日借记模拟税前现金、贷记应收，权益不因支付再增加。若实际支付证据日后取得，只能在对应实际basis内替代未结算状态，不能把模拟和实际两个版本相加。

公告对个人、基金、居民企业、QFII、沪深股通及部分限售股规定不同处理；个人／基金还可能在转让后补缴。故税前模拟转账不意味着税率0%，不保证等额净到账。未知税额、税后现金与投资者税后收益保持null。公告披露时间全部按DAY记录，午夜毫秒值不升级为真实首次公开时刻；供应商PIT认证不因本轮补证升级。

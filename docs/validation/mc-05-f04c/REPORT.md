# MC-05-F04C 真实历史行情与多粒度成交模型

用 Binance 公共归档和 R04B 认证快照回放了 NVDAUSDT 的一个连续 168 小时窗口。窗口内小时收盘、分钟收盘和分钟高低价均未达到有效订单的限价，小时收盘遗漏 0 次真实价格触及。A、B 两个 Paper 账户提交的五张买单全部到期，0 张订单的成交轨迹不同。共同时间网格上的期末权益均为 1,000 USDT，最大回撤均为 0%。[行情覆盖](DATA_COVERAGE.md) · [订单路径](PARTICIPATION.md) · [账务](FINANCIAL.md)

## 研究范围

实验使用 `[2026-08-05, 2026-08-12)` UTC 的 10,080 根分钟线、168 根小时线、7 根日线以及前一根已收盘小时线。公开可得性以实际归档回执和 R04B 快照取得时间为准。两组使用同一个 216.54 USDT 锚点、承袭 F04A 的几何 Grid、100 小时 TTL、1,000 USDT 初值、零库存、4 bps 手续费和 6 bps 逆向滑点。每小时 0.10 合约单位的共享容量是 F04A 的合成执行假设。C 只记录 A 组有效限价单的极值证据。

调度复用 Grid Paper 的小时观察、订单匹配、撤单和提交。分钟成交在 Paper 事务内写入报价和成交，小时观察接收期间的成交反馈并处理后续提案。风险及经济准入继续由现有 Grid 和 Paper 执行。研究保存两个独立账户的订单事件，按相同小时收盘坐标比较权益和最大回撤。按分钟额外采集的账户观测只影响成交时钟。细节见 [成交时序](EXECUTION_SEMANTICS.md)。

## 结果的适用范围

本窗口没有入场价格机会。最靠近有效限价的分钟低点仍高出 2.99 USDT，因此把报价检查从每小时一次加到每分钟一次没有改变账务，也没有触发容量、滑点或资金约束。本轮对成交观察粒度的敏感性为 `INCONCLUSIVE`。五张订单在同一个固定 TTL 下到期，F04A 的多 TTL、多市场路径配对显著性仍由其自身研究支持。本研究说明实际价格路径与订单有效期的重叠决定了分钟观察能否产生额外机会。

本次是一条真实市场路径。配对差值是条件于该路径和设定的确定性结果。分钟高低价之间的成交顺序、买卖报价、队列位置和可分配容量仍需额外数据。下一阶段可事先选定另一个有界、独立的历史窗口，保留相同 Grid 与容量，并用分钟触价筛查值得继续研究的订单事件。若新窗口出现触价，再在这些时刻补采逐笔成交或历史买卖盘与深度，用于验证同分钟顺序及容量假设。资金费为 `NOT_SIMULATED`，永续保证金及强平机制仍留待单独验证。

## 资源与复跑

采集预算为单标的 7 个 UTC 日、2 次 HEAD 和 28 次有界 GET，估计约 0.4 MiB。实际归档载荷共 337,031 字节，GET 阶段耗时 15.102 秒。单进程回放预算为 120 秒、256 MiB，先用 24 小时真实数据运行验收样本，再运行完整窗口。完整配对执行及账务核对耗时 1.669 秒、约 0.719 CPU 秒，本地回放输出在写入总审计前为 161,629 字节。Git 保留计数、订单和来源摘要，原始行情和 SQLite 账户保存在本地。

88 项定向测试通过，包括分钟与小时边界、到期小时撮合顺序、多分钟共享容量、分笔、拒绝、风险退出、含手续费的 FIFO 核算、原有小时基准和 Demo 桥接。正式回放与同输入复跑的结果 SHA-256 均为 `9570d0f0b83e2f11bb96a052c1c0205561860bb12e1928e81ca54843b638adef`。运行配置、行情身份、订单事件、配对及逐账户对账详见 [AUDIT.json](AUDIT.json)。

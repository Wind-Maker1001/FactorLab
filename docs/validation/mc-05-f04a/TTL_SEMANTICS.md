# MC-05-F04A 订单有效期语义

## 计时和撤单顺序

`GridExecution` 每处理一个新观察，递增一次观察序号。限单在形成提案时记住当前序号，达到 `当前序号 − 创建序号 >= order_ttl` 时进入到期撤单集合。提交、成交和撤单确认各有独立的递交序号，均不推动 TTL。F04A 的收盘价每隔一小时输入一次，所以一个观察间隔对应一小时。订单在提交的收盘价上没有成交机会。

`run_experiment` 先取得来自较早观察的未终结订单，再处理当前观察。Grid 更新账户标记、检查风控并标记应撤的订单。Paper 随后按订单顺序，使用当前收盘价、方向性滑点和剩余合成容量计算成交候选。符合条件的候选进入 Paper 事务，仍受仓位、抵押、最小数量、最小名义额及剩余换手预算等规则约束。撮合结束后，控制器才确认撤单并处理新提案。因此，**到期当小时仍可成交**。到期当小时全部成交的订单没有撤单记录，部分成交的订单可以撤销剩余数量。只要 Grid 已经请求撤单，该笔成交就不会生成反向订单。

168 小时路径包含初始价格和之后 168 个小时变化。初始订单最早在第一个小时变化对应的观察上参与撮合。TTL 为 168 时，它们在最后一个观察上达到到期条件，仍有一次撮合机会。更晚生成的反向订单有自己的计时起点，所以窗口结束时可能还有未结订单。

独立的 `GridStrategy.on_event` 使用不同顺序，在检查触价前就把限单置为 `EXPIRED`。本研究和 F03 使用 `GridExecution` 经 `run_experiment` 驱动 Paper 事务，记录的到期结果是控制器确认的 `CANCELED`。

## 重挂、风险和敞口

F03 冻结配置的 `expiry_reseed_limit` 为 0，三个 TTL 组均沿用。到期单确认撤销后释放对应预留，策略保留其当前网格状态，且不会因为到期而重挂。若另一个配置开启重挂，只有运行中遭确认的到期撤单才能触发待重挂状态。Grid 要等现有订单全部终结、账户可继续提案并且观察是完成的 bar，然后检查距上一轮重挂的观察间隔和次数上限。`expiry_reseed_interval` 约束重挂间隔，`expiry_reseed_limit` 限制次数，两者均独立于限单的年龄。

冻结配置使用几何网格和 `breakout='pause'`。越界暂停撤掉未终结订单并清除待重挂或待重建状态。回撤和换手限额也会请求暂停。一般配置还可以在突破时重建，或在撤单结算后提交减仓市价单。市价退出单没有限单 TTL，依然需要下一次价格观察及可执行容量。冻结的暂停模式只停止网格交易，已有库存继续按收盘价估值。若同一订单在突破暂停当小时也达到 TTL，`lifecycle` 将确认撤单归为 `TTL`，而 `risk` 记录状态转换触发的 `BREAKOUT`。突破撤单的表格计数按生命周期标签统计。

改变 TTL 会改变同时挂单的数量、抵押预留持续时间和后续反向单生成时点。较晚成交的买单会延长或新建库存敞口，也可能消耗同小时的合成容量，影响其他订单。不同期限在同一路径上的成交、挂单和库存轨迹要按实际账户对照。

## 触价诊断的范围

触价用带滑点的方向性收盘价对比提交后的已接纳限价。买单要求 `close × (1 + slippage) <= limit`，卖单要求 `close × (1 − slippage) >= limit`。撤单确认所在小时属于当时可检查的报价范围，撤单后触价只统计更晚的观察。后续触价说明价格越过已撤订单的价位，配对 Paper 账户用当时的订单顺序、共享容量和准入结果来判断交易是否发生。每小时只有一个合成盘口报价，无法观测小时内越价先后、可成交深度和排队顺序。

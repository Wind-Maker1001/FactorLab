# Binance USDⓈ-M Demo 时间同步与实时行情可靠性

基线为 `90f24841381d96b7aa0dd7f52fd8a6fd72715bf9`（[PR #210](https://github.com/Wind-Maker1001/FactorLab/pull/210)）。本次变更使用现有 Preview、账户对账、只读请求预算及中断路径。

## 原因与时间误差

F03 签名窗口的首个 `/fapi/v1/time` RTT 为 4.706 秒。按原中点估计，仅网络方向未知带来的不确定性就约 ±2.353 秒。`account` 返回 200，随后 `positionRisk` 返回 HTTP 400 / `CLOCK_SKEW`。协议将 Binance `-1021` 归为该类别。旧事件保留了类别，缺失原始错误消息、实际签名时间戳、校准 `serverTime` 和签名时的估计偏差。Binance 同时检查时间戳的超前容忍和到达时的有效窗口，因此历史证据无法确定拒绝的方向。默认 `recvWindow` 为 5000 毫秒。[F03 签名事件](../p7-r13-f03/demo-events.csv) · [Binance 时间校验](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)

F03 公开窗口第一轮 RTT 为 0.880 秒，接收时本机墙钟减 `serverTime` 为 2.424 秒。若服务端时间戳在请求期间生成且墙钟在该次调用中稳定，交易所相对本机的偏移在约 −2.424 至 −1.544 秒之间，中点为 −1.984 秒。第三轮的 `/time` RTT 为 8.207 秒，收到锚点时墙钟年龄已达 2.433 秒。顺序执行的 klines 和 book 又花了 2.658 秒，整批以 5.118 秒年龄触发 `STALE_POLL`。这是早期时钟锚点与后续串行请求共同消耗预算的结果。Windows 在本次实验前报告时间服务未同步，源为 Local CMOS Clock。相对偏移和服务状态仍无法给出历史签名打点时的独立 UTC 误差或任一方向的单程延迟。[F03 公开逐轮摘要](../p7-r13-f03/public-summary.json)

## 实现

Demo 校准用单调时钟包住 `/time` 调用，按 RTT 中点将服务端时间锚定到该时钟，再用单调时间推进。取第一个满足质量要求的样本，最多三次 GET。正常低 RTT 路径只取一次。初始不确定性为半 RTT 加 1 毫秒，默认上限 950 毫秒，并受签名窗口限制。估计按每秒 1 毫秒扩大不确定性，45 秒后刷新。普通刷新需要与上一估计在不确定区间内相容。墙钟同时保留为诊断，用于识别同步期间或签名前的跳变。

签名使用估计时间并保留现有 `recvWindow`。校准失效时签名 GET 先校准再构造签名，签名构造本身不发送 HTTP。既有 CLOCK_SKEW 恢复范围内最多重新校准一次并重签一次原 GET。官方只读观测的中断守卫会在首个请求异常后拒绝后续请求。订单提交、撤销和 UNKNOWN 恢复沿用现有状态与调度规则。

同一 Preview 窗口的签名客户端与实时 feed 共享校准。feed 以交易所时间下界冻结已闭合 Bar 范围，到达时用上界核算最老可能盘口年龄。轮内以单调耗时加当前校准不确定性验证 5 秒批次门限。klines 仍先取，盘口随后取，避免补数提前消耗盘口有效期。历史页只推进历史与游标，最新闭合区间由正常轮次交付。两次已交付盘口的市场时间差与单调接收时间差均受 30 秒约束。超限轮次在回调前暂停，普通 worker 可以从已持久化游标启动新的连续区间，固定 Preview 实验遵循原中断规则。

Python 3.14 使用确定性时钟运行高 RTT、非对称延迟、墙钟跳变、交易所漂移、过期、重签成功/失败及请求抵达时超过 `recvWindow` 的用例。行情用例覆盖分钟边界、慢 klines/盘口、部分请求失败、批次过期、历史补数、游标提交/恢复、重复/缺失 Bar 和两种盘口间隔超限。

## 官方 Demo 同窗观测

候选源码 `ae76c66c98d6cb0d0228d4d38fa81480844c3054`。实验 `binance-demo-reliability-a` 从北京时间 2026-11-20 01:46:26.088 开始，01:49:01.477 写入截止事件。配置 155 秒、600 GET、5 MiB、5 秒轮后等待，使用官方 `demo-fapi.binance.com`、已有 Demo 凭证和独立 Preview 状态。预算记录有 141 笔已保留并获得响应的 GET，均为 HTTP 200，POST 与 DELETE 均为零。较宽泛的客户端 GET 计数器为 142，因为把截止时预算守卫拒绝的下一笔调用也计入。该调用未获得发送许可。原始事件与摘要合计 224,921 字节。

01:46:37.389 的 `account_reconciled` 表明账户核验完成，持仓、挂单和 UNKNOWN 订单均为零。事件记录了 `account`、`positionRisk`、`openOrders`、持仓模式、`symbolConfig`、交易状态和签名杠杆规则读取成功。此后 12 个完整轮次均交付了有效盘口，连续 Bar 游标依次到达 01:46、01:47、01:48。01:47 开盘、01:48 闭合的 Bar 完整形成于窗口内，符合前瞻条件。01:45 和 01:46 开盘的 Bar 属于预热或启动前已开盘的区间。末轮被截止守卫中止时，最后一个 Bar 与盘口游标均未前移。

四次校准均在第一个样本通过。估计的交易所相对本机偏移为 −2219、−2193、−2195、−2201 毫秒。首个估计的不确定性为 ±253 毫秒，约束到 −2472 至 −1966 毫秒。重校准中最大的估计偏移变化约 25.9 毫秒，均在相邻样本的误差范围内。签名阶段的不确定性为 253–321 毫秒。签名时观测到的墙钟与单调外推的差值小于 0.05 毫秒，该窗口的时钟证据显示稳定的相对偏移。

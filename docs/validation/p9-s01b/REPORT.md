## 阻断原因和处理

5月22日冻结目标确实产生000540订单。`_execute_order()` 先同时检查 `trade_status`、`is_st`，再检查停牌；因此未知ST使订单在停牌拒单之前抛错。这不是仅遍历持仓触发的估值检查。ST随后用于涨跌幅限制，不用于停牌拒单、股份权益或收盘账面估值；确认不可交易后计算ST限价不是拒单所必需的。

本次**未修改执行器**，也没有改变检查顺序。发行人证据足以为同一证券提供有期限的ST与停牌连续性资格，因此复用现有 `MarketEvidence`、`apply_issuer_execution_st()` 和原执行路径，不建立第二套状态机。D05原四日授权保持原样，另加独立有限键集及停牌证据约束。非停牌原逻辑、ST限价、费用、滑点、FIFO和冻结目标均保持不变。

资格只覆盖000540.SZ的 **2023-05-22至2023-06-14这18个来源交易日**，用途仅 `EXECUTION_STATE`。需同时核对原始 `st_status=2`、适配器ST未知，以及已验证公告支持的 `suspended=1`、`trade_status=0`、缺失原收盘；变化则拒绝装载。不是把枚举2全局映射为ST，不是把所有停牌证券认作ST，也不授予成交、价格或正式估值权限。
